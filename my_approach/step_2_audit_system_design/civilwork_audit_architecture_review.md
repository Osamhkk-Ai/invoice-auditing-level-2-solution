## 0. الحكم

### **جاهز مع تصحيحات (ready with corrections)**

**السبب العملي:** أعدتُ بناء محرك التسعير من الصفر، بثوابت قرأتها من نسخ العقد وتحققت منها على الصور الممسوحة، فأعطى النتيجة نفسها التي يعلنها التصميم: **7,703 سطراً مطابقاً و43 سطراً متبقياً في 37 طلباً**. كذلك تأكدت الأرقام الهيكلية الأساسية ومجموعة Amendment No. 3 (89 سطراً في 72 طلباً). القلب الحسابي للتصميم إذن صحيح ويمكن البدء بترميزه الآن.

لكن هناك ثلاث مشكلات حرجة يجب تصحيحها **قبل** ترميز وحدات الدليل والمستوى الطلبي، لأن كل واحدة منها تنتج أخطاء بالجملة لا حالات فردية:

1. **خريطة سجلات CT في §4.2 خاطئة.** عبارة `imported stone` مربوطة فيها بـ D.41.010، مع أن السجلات الـ 51 التي تحمل هذه العبارة كلها تدعم سطور A.14.010 بكمية مطابقة. تطبيق الخريطة كما هي يصفّر 51 سطراً صحيحاً ويعلّم **44 طلباً سليماً** لا يعلّمها أي فحص آخر. هذا وحده قريب من كامل عدد الأخطاء المتوقع (45–72).
2. **Clause 31A تتعارض مع Amendment No. 3 في تحديد "الطلب الأول".** Amendment No. 3 (ص43) يقول إن التسوية تظهر على أول طلب "submitted **after** the date of issue"، بينما Clause 31A تقول "on **or** after". التصميم لم يرصد نص Amendment No. 3، وحسم التعادل بين الطلبات الثلاثة المقدَّمة في 2026-05-12 باختيار أصغر رقم (`PA-00006`). تحت نص Amendment No. 3 يكون الطلب الحامل `PA-00443` (2026-05-14).
3. **قاعدة العلم في §5.9 لا تعلّم غياب التسوية أو الإفراج عن المحتجزات.** هي تعلّم فقط إذا اختلف المبلغ أو وُجد إخلال A1/A3، بينما تعرّف §5.8 وQ6 الفئتين `adjustment_31A_omitted` و`retention_release_45A_omitted` دون تغيير `expected_total`. النتيجة أن فئة خطأ يذكرها README صراحةً ("an adjustment omitted or taken early") لن تُعلَّم أبداً، أي سلبيات كاذبة مضمونة كلفة كل منها 5.

وتوجد أخطاء كبرى أخرى: جدول الـ ablation مقيس على خط أساس غير المعلن؛ قاموس فئات الخطأ ينقصه ثلث أنواع الأخطاء المرصودة فعلاً؛ خطأ تقريب وسيط شُخِّص كضجيج؛ وسؤال DW (Q5) يستخدم ترتيبين متناقضين، والبيانات نفسها ترجّح أنه ليس خطأً. التفاصيل أدناه.

## 1. ما فعلته (المنهج باختصار)

- قرأت التصميم كاملاً (549 سطراً) والنسخة المجمّعة للعقد كاملة (43 صفحة)، بما فيها Part VII وكل الجداول والملاحق والوثائق الخمس. ثم رسمت من ملف PDF الأصلي الصفحات 24 و25 و26 و32 و36 و38 و43 كصور وقارنتها بالنسخ. **لم أجد أي فرق** في الأرقام أو الصياغة المؤثرة. في الصفحة 43 أكدت الصورة كلمة "submitted after the date of issue" حرفياً.
- كتبت محرك تسعير مستقلاً بـ `decimal` بخيارات تبديل لكل قاعدة، وحللت السجلات الـ 2,169، وأعدت حساب كل ادعاء رقمي في التصميم.
- فككت كل سطر من الـ 43 المتبقية ببحث شامل (brute force) على تركيبات السعر الأساس × عامل النطاق × عامل الأرض × العلاوة × الشريحة × الخصم، لمعرفة كيف بُني السعر المفوتر فعلاً.
- فحصت كل السطور الواقعة ضمن ±3 أيام من كل تاريخ سريان أو حد زمني (2025-05-01، 2025-09-28، 2025-10-01، 2025-11-01، 2025-12-01، 2026-01-05، 2026-04-01، 2026-10-01).

## 6. كفاية ترتيب المعالجة والحالة المخزَّنة

ما يصمد في التصميم:
- **الفرز العالمي قبل التسعير ضروري ومثبت:** الترتيب (`work_date`, `application_no`, `line_no`) هو الوحيد الذي يعطي 7,703. الترتيب بتاريخ الطلب يُفقد 72 سطراً، وعكس ترتيب رقم الطلب يُفقد 8. هذا يعني أن طلباً مقدَّماً لاحقاً بتاريخ عمل أقدم يغيّر شرائح سطور في طلبات قُدّمت قبله. لذلك **لا يمكن** معالجة الطلبات تدفقياً (streaming) بتاريخ التقديم؛ يلزم تحميل الكل ثم الفرز.
- عدّاد الشرائح بمفتاح (`item`, `contract_year`) كافٍ. واختبار الحساسية (مدفوع مقابل مدعوم) لا يغيّر أي سطر في هذه البيانات، لأن السطر الوحيد المصفَّر من بنود الشرائح هو `PA-00609-01` (D.41.010، سجل مفقود).

ما ينقص:
1. **حالة الطلبات الخاصة (31A/45A)** تحتاج قائمة الطلبات مرتبة بتاريخ التقديم مع تعريف صريح لكسر التعادل. التصميم يفترض أصغر رقم دون نص (C2).
2. **"اللاحق" في Clause 44** غير محدد بترتيب واحد (M4)، وقصّ الحد اليومي عند تعدد السطور لا يحدد السطر المقصوص (m9). يجب ترتيب واحد يُستخدم في H1 وH2 وE5.

## ملحق (أ): طريقة إعادة الإنتاج

البيئة: Python 3.11، pandas 3.0.2، PyMuPDF 1.27 (لرسم الصفحات فقط). كل المال بـ `decimal.Decimal`.

### أ.1 محرك التسعير المستقل (مختصر)

```python
from decimal import Decimal as D, ROUND_HALF_UP, ROUND_HALF_EVEN
import datetime as dt
C = D("0.01")
# S1 (Schedule 1 ص17-19)، ZONE، GROUND، SCH3، NIGHT، REST، BANDS، INDEX (2A)، FX (2B)،
# DISC_ITEMS = {C.32.030, C.32.010, D.41.020, B.23.010}، D4120 (S1 §1.2)، E54 (A2 §2.2) — كما في العقد.
def base_rate(code, wd, appdate):
    m = wd[:7]; r = D(S1[code][1])
    if code == "B.23.010": r = D("4120") if wd < "2025-05-01" else D("4385") if wd < "2025-10-01" else D("4450")
    elif code == "B.21.020": r = D("415") if wd < "2025-05-01" else D("431.50")
    elif code == "A.16.010": r = D("1480") if wd < "2025-05-01" else D("1524")
    elif code == "D.41.020":
        r = D("63.50") if wd < "2025-05-01" else D(D4120.get(m, "220.50")) if wd < "2025-12-01" else D("228")
    elif code == "E.54.010":
        r = D("876") if wd < "2025-10-01" else D("948") if wd < "2026-04-01" else D(E54.get(m, "1052"))
    elif code in ("C.32.010", "A.14.010") and wd >= "2025-11-01":
        if appdate >= "2026-05-12":                     # 31A: before issue -> old rate
            r = D("1984") if code == "C.32.010" else D("56.80")
    if code in INDEXED: r = (r * INDEX[m] / 100).quantize(C, ROUND_HALF_EVEN)   # 29A
    if code in USD:     r = (r * FX[m] / 100).quantize(C, ROUND_HALF_EVEN)      # 26A
    return r

def unrounded(code, zone, ground, night, wd, appdate):
    r = base_rate(code, wd, appdate)
    zf = ZONE[zone[:2]] if code[0] in "ABCD" else D(1); r *= zf
    if code in SCH3: r *= GROUND["G2" if wd >= "2025-09-28" else ground[:2]]      # 27A
    rest = dt.date.fromisoformat(wd).weekday() in (4, 5) and code in REST
    if rest: r *= 1 + D(REST[code]) / 100                                          # 8, P11
    elif night == "Y" and code in NIGHT and zf <= D("1.1"): r *= 1 + D(NIGHT[code]) / 100  # 27A
    return r

def discount(code, wd):
    if code not in DISC_ITEMS: return D(0)
    return D("0.08") if wd >= "2026-04-01" else D("0.05") if wd >= "2025-12-01" else D(0)

def price_all(lines, appdate_of):
    cum, out = {}, {}
    for r in lines.sort_values(["work_date", "application_no", "line_no_int"]).itertuples():
        q = int(r.quantity); u = unrounded(r.item_code, r.site_zone, r.ground_class, r.night_work,
                                           r.work_date, appdate_of[r.application_no])
        parts = [(q, 100)]
        if r.item_code in BANDS:                                                   # Sch 4 Part 3 + 3A
            k = (r.item_code, 1 if r.work_date < "2026-01-05" else 2)
            pos = cum.get(k, 0); cum[k] = pos + q; rem = q; parts = []
            for lim, pct in BANDS[r.item_code]:
                if rem <= 0: break
                if lim is None or pos < lim:
                    t = rem if lim is None else min(rem, lim - pos); parts.append((t, pct)); pos += t; rem -= t
        dsc = discount(r.item_code, r.work_date)
        rates = [(u * D(p) / 100 * (1 - dsc)).quantize(C, ROUND_HALF_UP) for _, p in parts]  # 28
        out[r.line_ref] = sum(rt * t for rt, (t, _) in zip(rates, parts))
    return out
# matched = count(out[line_ref] == Decimal(amount))  -> 7,703
```
